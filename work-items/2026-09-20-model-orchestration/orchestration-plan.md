# План субагентов для этого Work Item

## Scope And Acceptance Criteria

brief.md, AC1–AC8; architecture.md; tasks.md, T1–T4. Ведущий агент остается координатором.

## Host Evidence

Хост: Codex, сессия разработки 2026-09-20. Источник: предоставленные хостом контракты collaboration и фактические ответы инструментов.

Доступны создание субагента, продолжение задания, сообщения, список состояний и остановка. Хост имеет четыре суммарных слота с учетом ведущего агента. Для этого Work Item исполнители запускаются с наследованием настройки модели; точная наблюдаемая модель, токены и стоимость — Unknown. Наличие списка допустимых моделей не используется как основание менять ограничения хоста.

## Execution Mode And Rationale

Mode: same-model-delegation

Распределены независимо редактируемые контракты и сценарии. Дополнительный отдельный review проверяет семантику интеграции. Межмодельная экономия не заявляется; основная модель не переключалась.

## Assignments

- T1: ведущий агент; capability, Architecture, реестры, Core и шаблон плана.
- T2: flow_contract; Task Decomposition, Development, implementation capability, шаблоны задач и отчета. Задание содержит AC, границы файлов, правила сохранения чужих правок, ограничения и формат evidence.
- T3: behavioral_evidence; один новый structural test и восемь новых Runtime-сценариев. Задание использует принятый интерфейс capability и не меняет реестры или Runtime.
- T4: ведущий агент интегрирует и проверяет все изменения; orchestration_review выполняет отдельное ограниченное чтение контрактов без записи.

Запись T2 и T3 не пересекается. Итоговые проверки и документация выполняются после готовности их результатов.

## Budget And Execution Limits

Максимум два одновременно работающих субагента, две попытки выполнения задания суммарно, один уровень делегирования. Субагенты не создают новых агентов. Денежный/токенный бюджет пользователем не задан; telemetry Unknown. Новые внешние API и платные сравнительные прогоны не запускаются.

## Recovery And Resume

Перед повторным запуском сверять job IDs и изменения на диске. Ошибка локальной sandbox-проверки серверных тестов решается разрешенным запуском тех же тестов, без изменения продукта или ослабления проверок.

## Measurements And Limitations

Реальное native-делегирование и интеграция использованы при разработке самой фичи. Это не отдельная проверка установленного плагина и не тест переключения между разными моделями. Токены, стоимость и сопоставимый single-model baseline отсутствуют; экономия и превосходство качества не заявляются.
